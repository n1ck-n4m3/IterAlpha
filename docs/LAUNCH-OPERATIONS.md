# IterAlpha 站点与早期用户运营

## 这个站点运行在哪里

项目代码在本地工作区 `/Users/qz/Desktop/IterAlpha`，线上版本通过 Sites 发布。应用运行在托管的 Cloudflare Worker 环境，`DB` 绑定为托管的 Cloudflare D1 数据库。训练记录和邮箱记录在服务端数据库保存；浏览器里的访客 cookie 只用于找到该访客的训练记录。它不是创始人自己租用或管理的服务器和数据库账户。今后可迁移，但需要单独导出数据库、配置新部署和转移访问权限。

目前线上站点的访问模式是 **public**，持链接的测试者可以访问。这只改变访问门槛，不会自动把数据库转移到你自己的账号。Market 页只展示合成示例；Coinbase 实时行情适配器未启用。未来发布真实行情前必须核对对外展示、存储与训练分析的授权，不能把“公开 API”当成公开产品许可。邮箱删除与退订、反滥用和隐私告知也要随用户规模继续完善。

## 首页和两条训练路线

- `/`：产品介绍、互动式模拟决策预览、产品闭环、新手和进阶入口、早期体验邮箱表单。
- `/app?track=foundations`：新手训练；每轮 6 次决策，默认 1 小时间隔，也可选 15 分钟或 4 小时。每一步给出教学提示、可见价格变化、区间、成交量对比、推断与未知项。
- `/app?track=advanced`：进阶训练；每轮 8 次决策，默认 4 小时间隔，也可选其他间隔；揭示结果前只展示事实与不确定性。系统提供可点选的理由，无须键入判断依据；若用户主动记录，训练完成后可以在逐步复盘中回看。
- 两条路线都使用模拟价格。Market 页同样是合成示例，不参与训练结算。当前 AI 未配置时，每次决策后的教练卡和整轮复盘清楚标注规则反馈。

首页预览只是说明交互的合成示例；它不保存交易。真正的训练从 `/app` 开始。首页参考了 [Devolfs](https://www.devolfs.com/) 的清晰叙事和 [Rotli](https://rotli.co/) 的产品演示式互动，未复制其素材或代码。

## 邮箱收集

表单询问邮箱、起点和明确同意。用途写明为发送早期体验邀请与偶尔征询产品反馈；网站目前**不会自动发邮件**。提交后邮箱转为小写并去重，保存在 D1 表 `early_access_signups`。同一邮箱再次提交时更新起点和最近同意时间。隐藏的防机器人字段若被填写，服务端返回统一成功信息但不保存。

通过 Sites 的数据库读取工具可查看或导出 `early_access_signups`。请仅把邮箱用于表单同意的用途，不要在公开页面或聊天中贴出完整邮箱名单。如果用户要求移除邮箱，应在托管数据库中删除对应记录；当前产品尚未提供自助退订和删除界面，正式开放前需补齐。

## 发布与验收

1. 运行 `npm run check`、`npm test`、`npm run build`。
2. 本地预览使用独立 D1；依次应用尚未应用的 `drizzle/*.sql` 迁移。不要重复执行已应用的建表 SQL。
3. 发布到现有 Sites 项目，保持原有访问设置。Sites 发布流程在部署新版本前应用待处理的线上迁移。
4. 验收首页动态预览、暂停动效、两条训练入口、进阶理由与判断依据、复盘、邮箱表单成功与失败状态。邮箱测试使用专门的测试地址，不用真实访客地址。

当前合成训练盘可用于教学演示，但不能声称重放了真实历史市场或证明用户交易能力提升。历史回放和 AI 个性化反馈是后续数据与模型接入工作。

## 想独立部署到自己的服务器和数据库

当前源码已经在公开 GitHub 仓库，代码和 MIT 许可可用于独立部署；线上 D1 仍属于现有 Sites 托管项目。独立部署建议先建自己的 Cloudflare 账号，再创建 Worker 和 D1 数据库，把 `DB` 绑定到 Worker，按顺序运行 `drizzle/` 下的迁移，并在服务端设置 `OPENAI_API_KEY`、`OPENAI_MODEL`（AI 可暂不设置）。然后配置域名、HTTPS、错误日志、数据库备份以及访问限制。自建环境不会自动拥有当前站点里的训练记录和邮箱；迁移这些数据需要单独安全导出、导入和核对。

正式公开前先在新环境用测试账号检查：首页、新手和进阶完整回合、断点恢复、复盘、邮箱写入与删除，并确认行情供应商允许公开展示。不要把 `.openai/hosting.json` 中现有站点的真实 ID、任何密钥或用户数据推到公开仓库。详见 `docs/INTEGRATION-GUIDE.md`。
