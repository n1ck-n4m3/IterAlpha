# Decision Spider operating guide

## 当前可交付范围

蜘蛛使用真实行情和虚拟本金。网站没有交易所私钥，不调用交易所下单接口。

入口：`/app?view=spider`。主页、训练页导航均有 Decision spider 入口。

1. 选择交易对。默认 BTC/USDT；搜索覆盖当前交易所现货目录，向下滚动继续加载。
2. 新账户默认 Tape pulse，按采样行情每 5 秒评估。也可选择趋势跟随、区间反弹或放量突破；它们继续使用 1、5、15 分钟已收盘 K 线。详见 [短周期指南](FAST-SPIDER.md)。
3. 默认本金 10,000 个报价资产单位，单次入场分配可用现金的 20%。可展开仓位设置调整。
4. 点击 Start spider，观察自动成交、盘口、过程检查与盈亏。
5. 暂停会停止所有监控，包括止损。已有仓位保留，重新启动或主动平仓后继续。

不同报价资产分开记账，例如 ETH/BTC 的本金和盈亏以 BTC 计，不把 USDT、USDC、USD 当成完全等价。

## 真实行情与覆盖范围

币安使用官方只读域名 `data-api.binance.vision`，无需交易 API key。动态同步 exchangeInfo 中可交易的现货对，不硬编码少量币种。目录缓存 5 分钟，行情缓存 4 秒，页面按每轮开始时间安排约 5 秒刷新，网络延迟时延后且不堆积请求。并发相同市场请求合并。

图表提供真实 OHLCV；盘口提供最多 100 档深度，界面直接显示最接近成交价的 7 档。支持平移、缩放、十种图形、MA、EMA、布林带、MACD、RSI、成交量。指标仅由可见历史数据计算。

Coinbase 适配器已实现，但默认停用。其 2026-08-07 行情条款限制向组织外访客展示，以及将数据用于 AI/自动化系统。获得覆盖这些用途的书面授权后，在服务端设置 `COINBASE_MARKET_DATA_LICENSED=true`，再部署。没有获得授权时，不开启此配置。

参考：
- https://developers.binance.com/en/docs/products/spot/faqs/market_data_only
- https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-all-known-trading-pairs
- https://www.coinbase.com/legal/market_data

服务器出站连接被拒绝时，个人模拟可改用用户浏览器直接访问同一个官方公开接口；浏览器自身也受地区及网络限制，不使用代理绕过交易所访问限制。账户会保存该行情来源模式，不能在后台常驻执行。

断线、限流、缺失深度、下架市场等会显示不可用并阻止新成交，不使用假行情顶替。部署地区或交易所网络限制可能造成不可用。

## 策略与成交规则

- Trend rider：MA 7 高于 MA 25 且 MACD 柱状值为正时进入，MA 7 低于 MA 25 时退出。
- Range scout：RSI 从 30 以下恢复到 30 以上时进入，达到 60 时退出。
- Breakout hunter：最新已收盘 K 线高于前 20 根最高点，且成交量至少为前 20 根均值的 1.2 倍时进入，跌破 MA 7 时退出。
- 上述三套 K 线策略至少需要 40 根连续、已收盘 K 线，每根只处理一次。Tape pulse 则使用至少 30 秒真实新快照及前 10 档压力，不等待 K 线结束；阈值与费用门槛详见短周期指南。
- 同一蜘蛛持有一个多头现货仓位，不加杠杆、不做空、不重复叠加进场。
- K 线策略默认止损 1%、目标 2%，最长持仓 12 个信号周期；Tape pulse 默认止损 0.3%、目标 0.6%，最长持仓 2 分钟。保护退出按每次新行情检查。
- 账户从峰值回撤达到 5% 时尝试平仓并暂停；如果没有足够深度，无法虚构一个成功平仓，应由用户在行情恢复后处理。
- 买入按可见卖盘深度，卖出按可见买盘深度计算均价，再加保存的模拟不利滑点和手续费，缺省分别为单边 5bp 与 10bp，新账户可在设置中调整。入场价差超过 0.35% 时等待。
- 当前挂单量、最小数量、数量步长、最大数量及最低成交额会被检查。此账本用于教学，不声称完全复制交易所撮合、排队优先级、真实延迟或费率分层。
- 止损不保证按止损价成交。跳空或两次快照之间的波动按下一次观察到的可用盘口处理，不补造历史成交。

胜率 = 盈利的已完成往返交易 / 全部已完成往返交易。未平仓不进入胜率分母。盈亏区分已实现与未实现；未实现部分按最优买价、估计退出费用计算，实际平仓按盘口深度。

账户和成交保存在 D1，采用版本号比较更新，多个标签页或重复请求只能保存一份成交。服务器行情模式中，浏览器只发送控制指令。当前托管环境请求币安返回 HTTP 403 时，个人练习会使用官方支持 CORS 的浏览器直连行情，并向服务器提交受大小和结构限制的行情快照。服务器继续计算和保存资金、仓位、成交，不能由浏览器直接提交收益或余额。浏览器提供的价格无法独立验证，因此响应明确标记 browser-provided 和 rankEligible=false，不作为可验证排名成绩。访客记录绑定安全 cookie，登录后归并到当前账户。

## 运行方式与常驻服务

默认执行由可见网页驱动。浏览器直连行情的账户即使配置了常驻 runner，也只在网页可见时运行，常驻任务会跳过这些账户。页面切到后台时请求暂停；请求未送达时，下次检查发现超过 60 秒的监控中断也会暂停，不回放缺失时段的买卖。网站关闭后不会自行持续交易。

需要 24 小时运行时，在独立的常开 CPU 主机运行：

```sh
export ITERALPHA_SITE_URL=https://your-site.example
export SPIDER_RUNNER_KEY=your-separate-random-secret-at-least-32-characters
node scripts/spider-runner.mjs
```

服务端 Sites 配置相同的 `SPIDER_RUNNER_KEY`，重新部署。不要把 secret 放进浏览器、公开 GitHub 或聊天记录。脚本不需要 GPU 或交易所 API key，之后可和 5060 的模型服务放在同一台主机。应由 systemd、容器或其他进程管理器负责自动重启。只运行一份即可。

`POST /api/spider/run` 使用独立 bearer secret；轮询所有运行中的账户，每批最多 20 个。以少量内测用户为目标，用户数扩大时需要专门的队列、行情 WebSocket 聚合与工作进程。本次交付没有购买或部署这台常驻主机，因此默认仍是网页运行模式。

## 动效与声音

数字平滑过渡、K 线插值更新、盘口深度条动画、检查流程分段呈现、悬停光效和蜘蛛运动均已实现。流程状态来自服务器真实结果，动画不代表额外模型能力。

音频按钮在页面顶部。交互提示音、BGM、音量可独立控制。默认静音，点击后才创建 AudioContext。音乐是原创程序合成，无外部音频下载。隐藏页面会暂停音频。减少动态效果的系统设置会关闭非必要动画。

## 模型接入

当前蜘蛛的策略和风控由确定规则运行，未宣称已经连接模型或有盈利优势。

训练页已支持额外的开源模型检查接口。5060 到位后的配置见 `OPEN-MODEL-SETUP.md`。模型判断不直接获得资金控制权，也不把选项分数当成交易胜率。
